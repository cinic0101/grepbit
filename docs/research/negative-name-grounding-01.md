# Negative name binding: approved repair and bounded follow-up

2026-09-13. Implementation baseline `3fa90b7`; `ask-orchestration-v4`, unchanged
`plan-classify-json-v15` and bigram resolver. Root owned this slice. The owner
approved the ruler and intentional-absent-name clarification tradeoff, then
said to begin. Standing read-only PostgreSQL/Gemma and local commit authority
applied; no push, persistent database writes, new credentials or privacy opt-in.

## Finding and decision

The approved deterministic repair closes the measured partial-name NE gap.
On the unchanged authored grounding panel, correctly answered executions rise
from **36/40 to 40/40**, with the same **8/8 necessary refusals**. All four prior
short-negative errors now answer correctly rather than being hidden by refusal.
Keep this scoped runtime repair. This is not proof of general name/intent
understanding, a new-user holdout, deployment validation or release readiness.

## What changed

`application/literals.py` and `application/grounding.py` share an occurrence
walk; `application/ask.py` computes eligible negative columns from the effective
overlay and actual text type. The new walk includes only model-authored NE at
plan, measure-extra, ratio-operand and `without.filters` scope. A supplied index
does not authorize a column. Reviewed metric/segment definitions and nested
positive filters remain outside the new coverage.

Exact literals stay unchanged. Missing values with unique/normalized-exact
candidates bind in place, then undergo compilation, SQL policy and authoritative
existence rechecks. Ambiguous, absent, unavailable or stale bindings clarify.
Substitution is disclosed through the existing trace/assumptions; operator,
scope, NULL behavior and verification level remain unchanged. No new model
calls, keyword rules, plan fields, prompt, SQL construct or calculation card.

The owner explicitly accepted that an intentional exclusion of an absent name
can clarify on an opted-in column. Ordinary ungrounded exclusions still use
literal SQL semantics. The existing research bypass settings stay bypasses.

## Results and attribution

| Same authored index panel, two repeats | Earlier v3 | New v4 |
|---|---:|---:|
| Answerable executions answered correctly | 36/40 | 40/40 |
| Required refusals accepted | 8/8 | 8/8 |
| Short-negative wrong answers | 4 | 0 |
| Answer value comparisons across instances | 72/80 | 80/80 |
| p50 end-to-end seconds | 3.250 | 3.092 |

The new statuses are 40 answered, six clarify and two semantic-gap. The eight
required-refusal executions in this live panel are missing/ambiguous positive
name controls, not eight live absent-negative tests; negative refusal behavior
is covered by the approval rulers. All 40 answers have effective-computation
disclosure. Three fictional instances give 80 value comparisons and 88 total
acceptance judgments; neither is 80/88 independent questions.

Initial captured plan facts match the prior run in 45/48 executions. Three of
the four rescued negatives have identical initial plan hashes. The other POS
execution changed its abbreviated literal (the rest of its recorded structure
matches). All four still needed a unique candidate substitution; none was
rescued by the model producing the full stored name. The fixed-plan checks
cover both POS abbreviations, supporting the mechanism despite session drift.
We do not attribute the small latency change to the repair: these are successive
sessions on a shared endpoint, not a controlled latency experiment.

## Limits and next order

1. This fixes an execution-path binding omission, not metric selection,
   concept-veto false positives or component-versus-row misunderstandings.
2. Existing bigram similarity can still choose a wrong unique name in a larger
   catalog. No new language-specific exception was added and no arbitrary-name
   generalization claim follows from two small authored sources.
3. Nested positive EQ/IN existence coverage is intentionally not expanded.
   If prioritized, establish its own coverage ruler before changing behavior.
4. Absence/ambiguity on an opted-in negative name may intentionally refuse.
   Literal-intent overrides and a complete PII policy remain separate decisions.
5. Keep the existing lexical gate unchanged: the preceding study's six correct
   rescues also admitted eight additional wrong labeled pairs. No evidence here
   authorizes global gate removal or another unbounded prompt search.

Next measure unseen name questions/larger candidate collisions if available;
keep payroll component-scope and metric/lexical issues tracked separately. No
further semantic policy or live budget is implied by this completed slice.
