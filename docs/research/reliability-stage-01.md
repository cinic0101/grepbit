# Grounding, component scope and lexical veto: bounded replication

2026-09-13. Baseline `3c7b48f`; protocol:
[`../plan/reliability-stage-20260913.md`](../plan/reliability-stage-20260913.md).
Root implemented private experiment tooling, not a production feature.
Artifacts: `.artifacts/reliability-stage-20260913/`. Historical scores unchanged.

## Method and scope

48 distinct authored questions, 288 scheduled question executions, two serial
repeats reversing arm order. Gemma 4 31B, temperature zero, thinking off,
existing bounded one-repair policy; maximum 864 actual transport attempts.
Prompt `plan-classify-json-v15`, orchestration `ask-orchestration-v3` unchanged.
Different schema-comment arms are explicitly different model contexts, not
the same prompt input. Cases, contexts, complete expected recipes, independent
SQL oracles, payload hashes and source/driver identity frozen before live calls.

A has 12 public POS-store and 12 fictional-depot questions. Each compares
the identical schema and public-column overlay with the value index absent
or present. The controls cover exact/partial names, Chinese/English, spaces,
typos, tied names, missing entities, positive and negative predicates, and
multiple entities. POS uses read-only fixture SQL. Fictional depots use three
data instances with unequal amounts and an unmatched parent reference.

B has three domains (payroll/bonus, goods/tax, service/surcharge), each with
four intents in Chinese/English: main-component sum, component exclusion,
explicit zero-extra-component row filter, and separate sums. Each compares
baseline metadata, date-role comments, component-role comments and neutral
true technical comments. Date-role comments are an analogous clarification,
not byte-identical to the preceding pilot. Payroll uses the full sampling-zero
POS-test schema but exclusively fictional rows; the other two use small synthetic
schemas. Thus domain and schema complexity are not isolated factors.
All answers are replayed on three fictional instances with zero/nonzero/NULL
extra components and duplicate main amounts. No persistent DB COMMENT or data
mutation. For payroll the total comment characters are 151/440/483/561 across
the four arms: the neutral control is approximate in length, not token-matched.

C freezes 12 existing labeled cases in `metric_selection_ruler.yaml`, two
languages each, the first pre-labeled correct and wrong plan, and three existing
instances. This is 24 utterances, 48 labeled utterance/plan pairs, 288 offline
executions, **zero model calls**. It is a selected mechanism panel, not a random
sample of old artifacts or an estimate of deployed false-positive prevalence.
Only `ShapePack.concepts` is empty in the shadow. SQL, schema, literal, unsafe,
time/shape and overlay controls remain unchanged. Correct/wrong are the prior
semantic-plan labels; this is not full-answer certification of output labels.

## Reading the evidence

The new opt-in `disclosed-answer-v1` grader is unchanged. Expected full recipes
and SQL values are frozen; unlisted recipes remain `unassessed`, not silently
rescored. Post-run, independently demonstrated population/binding errors receive
a separate cause annotation. Value agreement alone does not establish intent.
Refusals are reported separately from answers. No arbitrary extra columns are
discarded to make a result pass; unknown recipe/relevance remains unassessed.

Preflight: 13 driver tests and 656 fixed-plan/compiler versus independent SQL
agreements. Of those checks, POS uses PostgreSQL and synthetic instances use
DuckDB; they are not 656 independent questions or all PostgreSQL comparisons.
An additional 36 independent PostgreSQL VALUES/DuckDB reference comparisons
agree, and all nine component-row contrasts differ as intended. Shared authored
SQL is not an independently developed engine oracle, but the arithmetic/scope
counterexample is explicit and not generated by the planner or compiler.

## Deterministic findings

### Negative entity binding escapes current grounding coverage

The live first repeat generated a short-name `ne` filter for both public-store
and fictional-depot exclusions. Both index arms answered with values that differ
from the complete-name exclusion oracle. These automatic grades remain
`unassessed`; the separate cause is confirmed by the retained filter-value hash
and a fixed-plan reproduction, not inferred merely from an unfamiliar recipe.

`application/literals.py:text_literal_checks` and
`application/grounding.py:resolve_plan_literals` explicitly cover `eq/in` only.
Thus `label <> 'Harbor East'` does not exclude `Harbor East Terminal`.
Twelve fixed-plan checks (three instances, index off/on, partial/full literal)
reproduce six wrong partial exclusions and six correct full exclusions without
any model call. The compiler faithfully executes the wrong selected binding;
this is not a SQL arithmetic defect. The coverage gap exists independently of
endpoint variation; actual model-selected literals can still vary between runs.

For positive partial-name and typo cases the frozen initial messages are
identical between arms (zero full-name hints). Their improvement can therefore
be localized to post-planning grounding rather than a changed prompt alone.
Candidate wire references already allow `ne` when the exact candidate is
advertised, but that does not extend post-miss resolution to an unadvertised
short negative literal.

This does not authorize rejecting every absent negative literal: excluding a
category that genuinely has no rows may be a legitimate query. The next change
needs an explicit negative-binding scope and absent/ambiguous negative controls,
not an unconditional new rule for every text inequality.

The completed grounding repeats yielded:

| Outcome | No index | Index |
|---|---:|---:|
| Correct answers / 40 answerable executions | 9 | 36 |
| Answerable but refused | 26 | 0 |
| Separately confirmed wrong negative bindings | 5 | 4 |
| Required refusal controls / 8 | 8 | 8 |

The index's four errors are two partial-exclusion questions repeated twice.
Without the index, an additional POS full-name exclusion flipped in repeat two:
the question supplied the full name but the plan shortened it. POS literal hashes
identify `遠東` in the first partial runs and `新店遠東` in the second; the
second no-index exact-name error also used `遠東`. They all differ from the
intended stored identifier `特約新店遠東`. This is a separate post-run diagnosis;
the frozen grader retains its original unassessed results.

The index improves coverage substantially, but fails the predeclared all-unique-
bindings correctness gate. Do not turn 36/40 into a universal grounding claim
or count eight protective refusals as eight correct numerical answers.

### Lexical veto has both real benefit and real harm

| Fixed labeled pairs | Current gate allows | Concept-only veto removed |
|---|---:|---:|
| Correct, 24 | 18 | 24 |
| Wrong, 24 | 16 | 24 |

All three instance replays agree on those gate decisions. Removing it rescues
six correct pairs but additionally admits eight wrong pairs. The 72 correct and
72 wrong executions per arm are repetitions of 24 pairs, not 72 unique cases.

False vetoes: English output-action `Return` on all-count/all-amount and both
service rows/entities requests, plus Chinese/English return-related output
labels. The gate also catches genuinely omitted return populations. It cannot
establish negation direction or distinguish rows from distinct entities merely
because a plan mentions a relevant column. Removing the veto cannot fix a
planner that already selected the wrong metric or population.

No production gate removal is supported. Conversely, these results do not
justify adding more lexical exceptions: they demonstrate role/scope confusion,
not a vocabulary deficit, and the panel is too small/selected to price the
tradeoff as a product-level accuracy improvement.

### Component choice is not the same as row population

In the completed payroll repeats, the English request to sum base salary by
payment quarter, excluding bonuses, produced `bonus = 0` with both baseline
and date-role metadata, twice each. Targeted component comments and neutral
technical comments both removed the error, twice each. The other seven payroll
questions agree with the frozen value oracles under every arm.
In particular the explicitly requested zero-bonus row filter remains correct;
the treatment is not merely suppressing all filters on bonus.

This establishes a component-versus-population error on that English question.
It does not establish that the targeted explanation causes a general semantic
repair: the non-semantic control achieves the same rescue. Likewise this is
not proof that every truthful comment is equally useful. The date arm is not
byte-identical to the earlier pilot, so its result must not be called a controlled
reversal of that exact previous intervention or attributed to endpoint drift.

## Live closeout

Complete: **288 question executions, 288 actual transport attempts**, zero
transport errors, retries or repair turns. Frozen source, schema, settings,
messages and reference-value identity equal at the end. The 656 oracle checks
were repeated for drift detection; do not double them into independent coverage.
Manifest: [`../../evidence/reliability-stage-01.json`](../../evidence/reliability-stage-01.json).

| Component study, 48 executions per arm | Accepted answers | Separately confirmed wrong row filters |
|---|---:|---:|
| Baseline | 46 | 2 |
| Date-role comments | 46 | 2 |
| Component-role comments | 48 | 0 |
| Neutral technical comments | 48 | 0 |

Both baseline/date errors are the same English payroll question, twice.
Goods and service each answer all 16 executions per arm correctly, including
their true row-filter controls. There is no measured improvement in those
domains because the baseline already succeeds. The targeted arm's perfect
panel is therefore not evidence of a specifically semantic or cross-domain
repair, and does not satisfy the promotion criterion.

All 246 served answers contain the effective-computation disclosure; this
includes 13 independently demonstrated wrong answers. Faithful disclosure
does not make a contradicted request correct. There are 26 answerable refusals
and 16 required refusals across both grounding arms; B has no refusals.
Across 142 repeated pairs retaining two plans, 133 full plan hashes are equal.
Hashes include aliases and are **not** the alias-free stability metric. One
observed correctness flip is the no-index exact POS exclusion. Other hash
changes must not be labeled regressions without semantic evidence, and none
establishes that endpoint batch composition caused the change.

Descriptive per-arm p50 seconds: grounding absent/present 2.930/3.2495;
component baseline/date/component/neutral 3.438/3.4735/3.5195/3.5295. Index
loading is outside these timings and refusal/answer mixes differ; do not
claim a controlled production latency improvement from them.

Validation: final private driver/shadow/analysis suite **22 passes**, existing
acceptance/ask/grounding focused gate **91 passes**, zero failures/skips.
Unsafe requests and unknown-column plans remain blocked in both lexical arms.
The fixed negative-binding checks reproduce current behavior; they do not
claim the bug is fixed. Production source, overlay, DB comments, prompt text,
served contract and legacy scores unchanged. No new full offline or 292-case
live regression is claimed; no candidate was promoted that would require it.

## Decisions and next step

1. **Grounding: retain evidence of benefit, do not promote as complete.** Next
   priority is the negative entity-binding coverage gap, including negative
   literal ambiguity, absent categories, nested predicates and disclosure.
   Establish the intended binding contract/rulers before changing the existing
   EQ/IN behavior. Do not change algebra or teach a store-name keyword exception.
2. **Component metadata: no production integration from this experiment.**
   Record the payroll failure and context sensitivity. Honest field definitions
   remain useful metadata, but a generic prompt patch is not justified by this
   neutral-control tie. No further prompt search within this budget.
3. **Lexical gate: keep production unchanged.** The selected panel exposes both
   false vetoes and protected wrong plans. Any replacement must measure both,
   preserve deterministic guards, and must not promote model agreement into
   intent certification.
4. **Research stage closed, product qualification still open.** A real unseen
   user holdout and explicit product risk thresholds are unavailable here.
   These authored questions and old selected labels cannot substitute for them.
   Human-correction cards are not reintroduced.
