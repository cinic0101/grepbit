interpretations. It must NOT change final Interpretation semantics, golds, the
occurrence resolver, checker, diagnostic acceptance or production verification.

One successful interface does not establish the other's success or justify
combining them automatically.

## F identity and candidate-universe contract

The original question-independent catalog remains the only source of operands.
Factor its canonical definitions into two source/table-bound ID catalogs:

- basis: table + count/sum/count_distinct + logical column;
- population: table + complete canonical predicate set, including explicit [];
- allowed pair: basis ID + population ID -> exactly one original candidate ID.

The model selects `{basis_id, population_id}` for value, or separately for
numerator and denominator, in one JSON response. Both keys are mandatory. The
outer pick/clarify/no_candidate envelope and label/refusal meanings remain the
approved Selection contract. Missing population does not mean all rows.

Factorization is a reversible change of presentation, not new algebra:

1. Every original candidate maps to exactly one pair; every allowed pair maps
   back to that original candidate, with its operand and all reviewed metadata
   unchanged. Full semantic signatures, not fixture-value coincidences, define
   the factor keys. IDs cannot depend on question, gold, display order or rows.
2. Do not admit the entire Cartesian product. A pair not present in the frozen
   original catalog is invalid even if each individual ID exists. Cross-source
   IDs, ID collisions, missing IDs, conflicting pair mappings and cross-table
   ratios refuse. Never substitute the closest pair or ignore one factor.
3. Resolve a pair to the original operand, then call the existing binder and
   domain/compiler. Do NOT take a filtered reviewed metric and replace its
   filters with the separately selected population. Metric provenance belongs
   on the allowed pair, not indiscriminately on every shared calculation basis.
4. A ratio needs distinct original operands on one table. The same basis with
   two different populations is legal; identical pairs are not. Labels remain
   output labels, never filters. No-candidate is not a correct semantic refusal.
5. Display all original definitions and reviewed metadata, with explicit
   unrestricted population and ambiguity choices. No question-based pruning,
   new default, preferred first entry, synthetic business vocabulary or gold
   answer choices. Capacity remains the original <=64 candidates/source.

The test-only factor specification can decompose the existing catalog and prove
these invariants offline. It is not an inference adapter and cannot be imported
by the live harness. The old single-ID binder should still reject the new shape;
forcing a missing-adapter import failure would not be useful red evidence.
