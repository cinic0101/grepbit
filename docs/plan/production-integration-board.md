## Acceptance applies to every capability

Planning selection, computation/binding, necessary refusal and full served
disclosure are one capability's acceptance, not a later semantic phase. Ordinary
records must not become DISTINCT entities; conversion must change values, not
labels; component windows/populations must remain independent; selection must
not discard the true winning entity because another measure is missing.

Keep correct/wrong answers, necessary/false refusals, unassessed outcomes and
operational failures separate. Blocked unknown repairs are not detected errors.
Known author/owner questions serve as regression; unseen questions are frozen
before execution and are not inspected to tune the same acceptance run.

New natural questions may be collected now using the existing intake mechanism,
not automatically logged from Web and not fabricated as independent users.
The owner deferred external upstream integration; use the existing local
consumer. Visibility, authorized fields, row caps and truncation are capability
entry conditions, not work postponed until release. Full PII/multi-tenant/high-
load deployment readiness remains a separate final scope decision.

## Finite failure handling and cleanup

A rejected candidate does not close the product capability. Review identifies
the failing layer and chooses a materially different evidenced approach, a
smaller useful delivery, or an explicitly blocked scope. Do not automatically
append prompt variants. Tests/doc/evidence inventory can proceed alongside live
work; freeze src/evals for each live phase and serialize shared model calls.

Move accepted logic to the shared serving owner and have research wrappers reuse
it. Remove replaced runtime implementations in the same slice; retain minimal
replay adapters and historical evidence needed to explain/reproduce decisions.
Do not delete the whole research directory or customer artifacts as cleanup.
