## 3. 排序裁定：別把原因改錯

兩輪原始基準回覆有 `direction: asc`；候選只給 `field`。
`OrderSpec.direction` 的既有預設是 **desc**，解析後才出現降序。
不是候選明確要求反向排序，也不是 PostgreSQL 替它選了方向。
**不要把共同 OrderSpec 預設改成 ASC。**

使用者已同意 `rows-direction-adjudication-v1`：完整、未截斷明細指定排序鍵，
但未明示／隱含方向、沒有排名或子集選取時，可接受已揭露的 ASC 或 DESC。

- 必須遵守排序鍵、NULLS LAST、穩定主鍵 tie-breaker、完整母體及重複次數。
- 明示升降序、最新／最早／最高／最低：嚴格遵守，不能任選。
- LIMIT、Top-N、OFFSET、分頁、服務截斷：不適用這項容許。
- 不能只比集合，也不能把 ASC 結果整串反轉當 DESC oracle；NULL／ties 會錯。

重用 `evals/answer_acceptance.py` 的 `disclosed-answer-v1`：各允許解讀分別
提供 typed plan、獨立 ordered SQL、context hash 與 evidence ID。
不是新增自然語言解析器，也不是自動替所有題目增加第二個答案。
這次是**觀察後、使用者明確裁定**，兩組一致套用並保留原分數；未來新題仍須
在呼叫前固定 annotation。測試：`test_rows_direction_adjudication.py`。
