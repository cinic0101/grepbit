## 3. Ordering adjudication: preserve the correct attribution

Both original baseline completions explicitly supplied `direction: asc`.
Both candidate completions supplied only `field`. The existing
`OrderSpec.direction` default is **desc**; parsing supplied that direction.
The model did not explicitly choose reverse order, and PostgreSQL did not choose
the direction. **Do not change the shared OrderSpec default to ASC.**

The owner approved `rows-direction-adjudication-v1`: for complete, untruncated
details with specified sort keys but no explicit/implied direction, ranking or
subset selection, accept either disclosed ASC or DESC.

- Still enforce the keys, NULLS LAST, stable primary-key tie-breakers, complete
  population and multiplicity.
- Explicit direction and latest/earliest/highest/lowest requirements are strict.
- LIMIT, Top-N, OFFSET, pagination and service-truncated results do not qualify.
- Do not compare only sets or reverse an entire ASC oracle to obtain DESC:
  doing so can reverse NULL placement and tie-breakers incorrectly.

Reuse `evals/answer_acceptance.py` and its unchanged `disclosed-answer-v1`
format: each allowed interpretation has a typed plan, independent ordered SQL,
