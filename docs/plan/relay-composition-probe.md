## Two factors and separate outcomes

- P: original relay instructions versus the already-tested checklist replies.
- E: prose alone versus client-retained original structured tool evidence next
  to the unchanged prose. The client copies evidence; the model never regenerates
  it or chooses which evidence to attach. This package is a private experiment,
  not a new externally consumed API or user-visible renderer.

Four cells reuse the same replies. Report prose all-obligations scores unchanged
(8/12 and 10/12), exact evidence retention separately, and cost (zero new model
calls). Do not score a prose failure as a successful answer just because an
attachment contains the missing fact. Evidence-off means no separate structured
attachment, not that the prose contains no evidence. This is a mechanical
composition check, **not a causal trial of model interaction or generalization**.

## Rulers and controls

Exact-copy checks bind to the received payload, not a model-supplied hash.
Require nested copy isolation; fail the check if evidence is removed, modified,
or swapped to another request. NULL/zero, truncation, verification and operational
status must survive. Keep payload fields as data, not instructions. Use synthetic
corruption and contradictory-prose controls to expose the boundaries:

- A matching digest proves copy integrity, not correctness of the tool answer.
- Wrong source facts can be copied perfectly; conflicting prose is not repaired.
- A retained warning does not prove a UI displayed it or a human read it.
- Request ID/digest matching is not authentication, authorization or tenant isolation.

Freeze the script/protocol/input identity before local MCP calls. Research tests
validate the intended copy/score accounting; no semantic red-ruler claim is needed
for a new private copy probe. Stop on input/hash drift or unexpected payload shape.
No adaptive prompt changes. Complete tests, probe, report, roadmap and a compact
safe evidence manifest; reuse the unchanged-source 1,864-test offline gate.

## Broader combination experiments, after this probe

Choose mechanisms by error stage and evidence source, not by how many agents can
be chained. For planner candidates use a baseline, X only, Y only and X+Y on the
same frozen panel. Inspect paired rescues AND new wrong answers/false refusals,
unknowns, per-family results and latency/call budget. A scalar interaction
`score(X+Y) - score(X) - score(Y) + score(baseline)` is descriptive; uncertainty
and hard safety controls remain separate. Do not compare unlike historical panels
or select the winning answer using a gold label available only in evaluation.

Known source-only gate variants already lose on adversarial controls. Combining
them with another same-model reviewer does not supply independent request-role
evidence. Do not revive rejected paths merely by bundling them. The next useful
planner pair needs a specific complementary-evidence hypothesis and frozen rescue/
harm controls before live spend. New user questions are still needed to estimate
how frequently the observed families matter to the actual product.
