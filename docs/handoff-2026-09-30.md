The design, in short (the contract is authoritative):
- `--gate --candidate C --baseline-candidate B --route R --owner-authorization-reference G --panels P…`.
- Offline and dev-tier only. It prints JSON and exits 0 whatever the verdict.
- Baseline runs are every indexed run with B's bytes. A sentinel run with B's
  bytes must exist under grant G.
- There must be exactly one run with C's bytes under G (no best-of).
- Per-input classes are `fixed`, `broke`, `unchanged_*`, `excluded` (a flaky
  or insufficient baseline) and `unassessed`.
- Verdict, first match: `regression` > `inconclusive` > `passed` > `no_fix`.
- Refusals give `invalid_manifest` plus a closed `gate_refusal` reason.

**Test state on `25d5424`:**
- `PYTHONPATH=tests:. .venv/bin/python -m unittest test_evaluate_gate test_evaluate_replay`
  ran 13 tests: 11 pass and 2 fail.
- The replay and aggregate rulers pass, so the `aggregate()` refactor
  preserves behavior.
- The gate CLI test passes.
- `test_gate_classifies_…` and `test_gate_refuses_…` fail. **The cause is in the
  ruler's fixture, not the gate:**
  - The fixture makes baseline "wrong" rows with invalid JSON (`broken=`).
  - A graded row with an operational error (`invalid_json`) counts as
    unassessed in the aggregate taxonomy, so input `x` becomes `insufficient`
    instead of `stable_wrong`.
- The full suite was not run on the branch.
